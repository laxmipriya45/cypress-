--------------------------CYPRESS architecture-----------------
Cypress runs partly in Node.js and partly in the browser.
Tests execute inside the browser, while a proxy server in Node.js handles network communication.
It uses WebSocket for real-time interaction, which makes it fast and reliable.

ALerts:  There are 3 main alert types (methods):
1.alert()
2.confirm()
3.prompt()

---Main Cypress Alert Methods / Events
1.window:alert-->   cy.on('window:alert', (text) => {  //only OK
                    expect(text).to.contains('Hello')
                    })
2.window:confirm-->  cy.on('window:confirm', (text) => {  // OK/Cancel
                         return true   //    
                         })   
3.window:prompt-->  cy.window().then((win) => {              // input box
                    cy.stub(win, 'prompt').returns('Laxmi')
                    })
//An alert is a popup message displayed by the browser. There are three types of alerts: alert, confirm, and prompt.
In Cypress, alerts are handled using cy.on('window:alert') and cy.on('window:confirm').
We capture the alert message and verify it using assertions like expect().to.contains().

----Alerts are browser popups. In Cypress, we handle them using cy.on() and verify the message using expect().

CUCUMBER FRAMEWORK----
In Cucumber, we write test cases using Gherkin language, which uses keywords like:

Given → Pre-condition (initial setup)
When → Action (what user does)
Then → Expected result (verification)


Feature → What feature you are testing
Scenario → One test case
Given → Start
When → Action
Then → Result
